# ClinicCare — Appointment & Medical Records System

A console-based clinic management system written in core Java (no external
libraries, no build tool). A patient registers once, receives a permanent
patient ID, and from then on can book consulting slots and read back every
prescription ever written for them. Doctors work the other side of the same
data: day schedules, prescriptions, patient files. A manager gets the numbers.

Built for the VITyarthi "Build Your Own Project" submission for the Java
programming course.

---

## Features

**Module 1 — Patient Management**
- Registration with full validation (name, 10-digit Indian mobile, age, gender, blood group)
- Permanent auto-generated patient ID (`P-1001`, `P-1002`, …)
- Duplicate phone number detection
- Search by partial name for patients who forgot their ID
- Profile updates

**Module 2 — Appointment Scheduling**
- Five doctors across five specializations, eight 30-minute slots per working day
- Live slot availability, shown before you choose
- Thread-safe booking — a slot can never be sold twice, proven by a test with 25 competing threads
- Cancel and reschedule, with ownership checks (you cannot touch someone else's booking)
- Automatic senior-citizen discount (20% off for age 60+)
- Sunday closure and doctor-leave handling
- 7-day availability grid (2-D array)

**Module 3 — Medical Records**
- Doctors write a prescription against a completed appointment
- Structured medicine lines: name, dosage pattern (`1-0-1`), duration
- Diagnosis, advice, optional follow-up date
- Full patient history, newest first, plus a distinct list of past conditions
- Writing a prescription automatically marks the appointment `COMPLETED`

**Module 4 — Reports & Analytics**
- Appointments per doctor with a text bar chart, and the busiest doctor
- Appointment status breakdown (`BOOKED` / `COMPLETED` / `CANCELLED` / `NO_SHOW`)
- Revenue total (computed recursively)
- Patient age distribution
- Most common diagnoses, ranked
- Clinic-wide 7-day load grid

**Cross-cutting**
- Two background threads: auto-save every 20s and an appointment reminder scanner
- Crash-safe writes (write to `.tmp`, then rename)
- Six custom exception types with error codes
- Runtime data dictionary generated by reflection (System Info screen)

## How to run

You need a JDK (17 or newer) with normal desktop support (the default JDK
from [adoptium.net](https://adoptium.net) or your OS package manager is fine;
a *headless-only* JRE cannot open the GUI window). Check with `java -version`
and `javac -version`.

**Linux / macOS**

```bash
javac -d out $(find src -name "*.java")
java -cp out com.clinic.Main          # opens the Swing GUI
java -cp out com.clinic.Main --console   # runs the original text menu instead
```

**Windows (PowerShell)**

```powershell
javac -d out (Get-ChildItem -Recurse -Filter *.java src | % FullName)
java -cp out com.clinic.Main
```

**Windows (cmd)**

```cmd
dir /s /b src\*.java > sources.txt
javac -d out @sources.txt
java -cp out com.clinic.Main
```

By default data is read from and written to `data/`. Pass a different folder
as an argument: `java -cp out com.clinic.Main mydata`. Combine flags in either
order, e.g. `java -cp out com.clinic.Main --console mydata`.

The staff/doctor desk is protected by the PIN **1234** (`StaffLoginPanel` /
`MenuApp.STAFF_PIN`).

### Two front ends, one engine

`com.clinic.gui` (Swing) and `com.clinic.ui` (console) are two independent
presentation layers sitting on top of the exact same `service`, `model` and
`storage` packages — neither one contains any business logic of its own. That
separation is what makes both possible from one codebase: `PatientService`,
`AppointmentService`, `RecordService` and `ReportService` have no idea whether
a button was clicked or a menu number was typed.

| | GUI (default) | Console (`--console`) |
|---|---|---|
| Package | `com.clinic.gui` | `com.clinic.ui` |
| Entry class | `GuiApp` | `MenuApp` |
| Toolkit | Java Swing | `java.util.Scanner` |
| Best for | day-to-day use, screenshots for your report | quick testing, low-resource machines, grading environments without a display |

## How to test

```bash
javac -d out $(find src test -name "*.java")
java -cp out com.clinic.test.SelfTest
```

49 checks across 8 groups. The harness exits with code 1 if anything fails, so
it drops straight into a CI pipeline. Current state:

```
  PASSED: 49    FAILED: 0
```

The most interesting test is `testConcurrentBooking()`: 25 threads attempt to
book the identical slot at the identical moment. Exactly one must succeed and
24 must be rejected with `SlotUnavailableException`. Delete the `synchronized`
block in `AppointmentService.book()` and this test starts failing — which is
the point of having it.

## Notes for reviewers

- **Why CSV and not JDBC?** The storage layer sits behind the `Repository`
  interface (`loadAll`, `saveAll`, `backendName`). `CsvRepository` is one
  implementation; a `JdbcRepository` using `Connection` / `PreparedStatement` /
  `ResultSet` would be a second, and `Main` would change on exactly one line:
  `Repository repository = new CsvRepository(dataDir);`. The schema for that
  table design is in `docs/DESIGN.md`.
- **Known limits:** single-user console application; the staff PIN is a
  constant, not hashed credentials; CSV is not a substitute for a real database
  under load. These are listed honestly under Future Enhancements in
  `docs/DESIGN.md`.
